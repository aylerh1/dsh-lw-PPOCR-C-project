# 项目经验总结

## 一、项目经验总结

### （1）项目介绍
本项目基于 C11 与 WebAssembly / 原生编译双推理架构，为 DeepSeek Harness (dsh) 与现代容器化微服务打造超轻量、免安装臃肿依赖的高性能离线 OCR 解决方案。
数据流向为：用户或 Agent 传入本地图片绝对路径、Buffer、Data URI 或 Base64 编码流；在 **DSH 插件端**，通过轻量级解码器转为 BGR 像素流并由纯 WASM 内核完成离线推理；在 **高并发 Web/API 容器端**，通过 Go 原生编译级图像解码器（5~15ms）极速解压为连续交织 `BGR8` 像素切片，经 CGO 零拷贝指针直接输入常驻底层的 `lw.PPOCR.C` 原生 C11 引擎，借助 AVX2 + FMA SIMD 向量指令集与 4-Worker 多线程池并行完成文本区域检测（DET）、文字方向分类（CLS）与字符识别（REC），最终输出包含结构化全文文本、单行高精度置信度与四点几何包围盒的标准化 JSON 数据，彻底根除传统 OCR 方案在智能体生态中依赖沉重（动辄数 GB）、进程冷启动卡顿（1.x 秒/页）与高并发内存膨胀的痛点。

### （2）总体技术架构
技术栈涵盖：C11, GCC/Clang 优化编译 (-O3 -mavx2 -mfma -pthread), CMake 静态库构建, Go 1.24 (CGO), WebAssembly (WASM), DeepSeek Harness (DSH), Cordis IoC 插件微内核, Docker 多阶段构建, Alpine Linux。
- **底层推理内核**：原生 C 静态库 (`liblw_ppocr_c_static.a`, 仅 514KB) 与官方预编译 WASM 双通道资产，结合 PP-OCRv6 tiny 轻量模型资产（总计仅约 7MB），实现零外部框架依赖的纯离线推理；
- **服务中间层**：Go 高性能 HTTP 并发服务通过 CGO 深度绑定原生 C 引擎，常驻预热模型，消除了任何子进程或解释器开销；同时提供 Cordis IoC 微内核热挂载与符合 OpenAPI / JSON Schema 规范的 Agent Tool 自动注册；
- **容器与交付层**：采用多阶段 Docker 镜像构建，剥离所有编译器与 Node.js 运行时，产出仅 **28.8MB** 的极简生产级镜像，单页 OCR 全流程延迟压缩至 **15~30ms**（提速 50+ 倍），常驻内存稳定在 **~30MB**。

### （3）总体功能架构
总体功能划分为四大模块：
1. **高性能图像预处理引擎**：支持本地路径、Base64、Data URI 与原始二进制输入；插件端集成纯 JS 跨平台解码，服务端集成 Go 编译级 PNG/JPEG/BMP 原生高速解码与交织 BGR8 转换器（耗时仅 5~15ms）；
2. **多核向量加速 OCR 推理流水线**：集成官方 PP-OCRv6 tiny 资产（det.lwm, cls.lwm, rec.lwm, ppocr_keys.txt），通过 AVX2/FMA 向量融合加速与多 Worker 线程池，实现毫秒级端到端文本检测、方向校正与识别；
3. **几何后处理与排版重构引擎**：基于 DBNet 多边形轮廓后处理生成四点包围盒，提供 horizontal-ltr、vertical-rtl 等多种阅读顺序几何排序与全文排版重构；
4. **双模生态接入与交互终端**：
   - **智能体生态**：遵循 Cordis IoC 生命周期向 Context 挂载 `ctx.ocr`，向大模型暴露具备严格 Schema 校验的 `ocr_recognize` 工具；
   - **现代化 Web UI**：内置深色玻璃拟态单页前端，支持截图粘贴（Ctrl+V）、拖拽上传、图上多边形框线高亮标注、性能看板与一键复制。

### （4）项目优点
1. **极致性能飞跃与毫秒级低延迟**：通过原生 C11 + AVX2 向量加速与 Go CGO 常驻模型交互，将原方案单页 1.x 秒的耗时大幅压缩至 **15~30ms**（性能跃升 50+ 倍），客户端往返平均仅需 24.8ms。
2. **容器镜像极致瘦身与超低内存**：采用多阶段静态构建，剔除 Node.js 及重型依赖，Docker 镜像体积由 155MB 锐减至 **28.8MB**（瘦身 81%）；多线程常驻内存仅稳定在 **~30MB**。
3. **真正离线与零重型环境依赖**：无需 Python、CUDA、OpenCV 或 ONNX Runtime 等数 GB 运行时包，无需宿主机配置 C/C++ 编译器，内置约 7MB 精简 LWM 模型，开箱即用。
4. **智能体深度兼容与高容错**：Agent Tool 严格遵循标准 JSON Schema Object 规范，杜绝 Gemini/Claude 等模型 Function Calling 时的 400 校验异常，并内置多候选参数自适应容错解析。

### （5）项目缺点
受限于端侧极小轻量化模型（7MB）与端侧推理设计，针对极端倾斜畸变、极端艺术变形字或超低对比度复杂背景图像的识别召回率略低于云端百亿参数多模态视觉大模型（如 GPT-4o / Gemini 1.5 Pro），适用于高并发、离线私密、低延时与边缘容器场景。

## 二、项目经验的简历式总结：

### 项目名称
dsh-lw-PPOCR-C-project（基于 lw.PPOCR.C 的轻量离线 OCR 插件与原生 AVX2 容器服务）

### 担任角色
核心架构与开发负责人，主导底层 C 源码静态编译优化、Go CGO 原生引擎绑定、DSH 智能体微内核集成与 Docker 容器极致瘦身

### 时间段
2025年6月 - 2025年8月

### 项目描述
本项目是针对多模态智能体框架 DeepSeek Harness 与边缘容器场景设计的高性能、零重型依赖离线 OCR 系统。针对传统 OCR 方案强依赖 Python/OpenCV/ONNX 导致镜像体积数 GB、环境冲突与启动缓慢的问题，本项目引入纯 C/WASM 离线推理架构与模型内嵌方案；针对早期动态拉起 Node 进程导致 OCR 单页耗时高达 1.x 秒、内存波动大的性能瓶颈，主导重构了**基于 C11 原生静态编译（AVX2/FMA SIMD 优化 + 多线程 Worker 池）与 Go CGO 内存直连的高性能常驻服务架构**；针对容器化部署需求，设计了多阶段 Docker 构建流程，彻底移除非必要运行时，实现了镜像体积与推理速度的极致优化。

### 项目业绩
1. **性能突破 50+ 倍**：彻底消除子进程 Fork 与重复模型载入开销，结合 Go 编译级前处理与 C11 AVX2 向量加速，将单页推理耗时从 **1.x 秒压至 15~30ms**，接口端到端往返延迟仅 24.8ms，满足工业级高吞吐实时识别需求；
2. **容器体积缩减 81%**：通过多阶段构建剔除所有编译器与 Node.js 运行时，产出纯静态服务，Docker 镜像体积由 **155MB 压缩至 28.8MB**，容器常驻内存平稳控制在 **~30MB 级别**；
3. **零环境依赖与极简交付**：全套 C 静态库、WASM 运行时与 7MB 精简 LWM 模型实现资产内嵌，无需安装 Python 或本地 C++ 工具链，支持通过 GitHub 仓库或 Docker Compose 一键拉起；
4. **大模型调用高容错与生态赋能**：基于 Cordis IoC 实现微内核服务注入，规范化 OpenAPI / JSON Schema 工具定义，彻底解决 Gemini/OpenAI 模型 Function Calling 400 校验异常，实现大模型自动化调用与玻璃拟态 Web 界面双重赋能。

## 三、项目经验的一句话总结

基于 lw.PPOCR.C 与 Go/CGO 的轻量级离线 OCR 系统：通过 C11 AVX2 向量加速与 Cordis 微内核架构，实现零 Python 依赖、28.8MB 极小镜像与 15~30ms 单页极速推理，完美兼顾智能体插件生态与高吞吐容器化服务。
